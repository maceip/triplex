# Triplex Implementation Plan

## What Triplex Actually Is

Based on exploring your artifacts, Triplex is building a modern voice agent that:

1. **Uses the Inherent audio gate** (from `~/inherent`) to quickly filter if audio is interesting
2. **Leverages recovered Cosmo models** you have in `~/Downloads/cosmo_recovered_large_assets/`:
   - `audio_frontend.tflite` - mel spectrogram extraction
   - `audio_gatekeeper_edgetpu.tflite` - the actual gatekeeper
   - `bert_v0_*.tflite` - BERT for intent classification
   - `voicelm_*` - end-to-end audio models (SoundStream encoder/decoder)
   - `gecko_*` - embedding model
3. **Connects to a voice LLM** (GPT-4o-audio, Gemini Live, or local)
4. **Deploys on Android** using the infrastructure from `~/tenet-android` and `~/cosmo-dev`

## Key Technical Decisions

### 1. Audio Frontend
- Use `audio_frontend.tflite` from Cosmo (verified working)
- Or implement in Python with torchaudio matching specs:
  - 16kHz mono
  - 128 mel bins
  - 20ms hop (160 samples)

### 2. Gatekeeper
- **Option A**: Use Inherent model you trained (`~/inherent`)
  - Pros: You own it, can retrain, known contract
  - Cons: Need to export and integrate

- **Option B**: Use Cosmo's `audio_gatekeeper_edgetpu.tflite`
  - Pros: Already optimized for EdgeTPU
  - Cons: Fixed weights, need to understand input contract

### 3. Voice LLM
- **Option A**: Cloud (GPT-4o-audio, Gemini Live)
  - Pros: Best quality, streaming
  - Cons: Latency, cost, requires internet

- **Option B**: VoiceLM from Cosmo assets (local)
  - Pros: On-device, no API costs
  - Cons: Need to wire up the 6-model pipeline, partial file missing

- **Option C**: Whisper + local LLM (Ollama, etc.)
  - Pros: Flexible, open source
  - Cons: Two-step pipeline adds latency

### 4. Deployment
- Android-first (using Cosmo architecture as reference)
- Python prototyping for quick iteration
